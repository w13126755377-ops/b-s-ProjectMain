# 演示视频脚本（企业审批系统大程答辩演示）

> 目标时长 6~8 分钟。按作业要求覆盖：三类流程全链路、自定义模板、状态机规则、统计、通知、
> 移动端适配、增强功能、docker 部署。每个环节给出**操作路径 + 镜头要点 + 口播要点**。
> 建议录制前先在本地完整跑一遍 `node backend/scripts/e2e.mjs` 确认环境就绪。

---

## 0. 环境启动（0:00 - 0:30）

**操作**：终端执行 `docker compose up -d`（首次自动建库建表 + 种子数据），浏览器打开 `http://localhost:8080`。

**口播**：
> 系统采用 Docker Compose 一键部署：MySQL 8 + Node 后端 + Nginx 前端三个容器。
> 数据库首次启动自动执行建表与演示数据脚本，脚本幂等，可重复初始化。

**镜头**：终端 compose 输出 + 浏览器登录页。

---

## 1. 注册 / 登录 / 部门确认门禁（0:30 - 1:20）

**操作**：
1. 注册页：新用户 `demo01`，密码 `Demo@123456`，选择"研发部"注册；
2. 登录 `demo01`，进入"发起申请"任意填一张差旅单 → **提交** → 报错提示"部门归属尚未经管理员确认"；
3. 退出，登录 `admin / Admin@123` → 管理后台 → 用户管理 → 确认 `demo01` 部门归属（并演示操作留痕）；
4. 回到 `demo01` 重新提交 → 成功。

**口播**：
> 注册用户默认只是普通员工，部门归属必须由管理员确认后才能提交申请，权限全部由服务端强制。

---

## 2. 采购申请全链路（1:20 - 2:50）

**操作**：
1. `zhangsan`（研发部负责人）登出，`sunqi / Sunqi@123`（研发部员工）登录；
2. 发起申请 → 采购：填 2 条明细、2 家报价（选**价格更高**的那家）→ 不填说明直接提交 → 报错"未选最低价须说明"；
3. 补上选择理由，上传报价附件（演示 JPEG/PNG/PDF 限制：传一个 .txt 被拒），保存草稿 → 提交；
4. 详情页展示：**CG+日期-序号**唯一编号、审批链时间线（部门负责人 → 财务）、金额为拟选供应商总额；
5. 登录 `zhangsan` → 待办中心 → 批准（填意见）；登录 `wangwu / Wangwu@123` → 批准 → 通过；
6. 登录 `sunqi`：详情页看到完整审批日志（节点、操作人、意见、时间）；右侧通知弹出"申请已通过"。

**口播**：
> 采购需 ≥2 条明细、≥2 家报价或单一来源说明；未选最低价必须说明原因；提交时快照审批链，
> 每一步审批都有日志留痕，日志不可修改。

**镜头**：双窗口并列——左窗口 `sunqi` 详情页，右窗口 `zhangsan` 审批，审批后左窗口**实时刷新**（SSE 推送）。

---

## 3. 差旅 + 关联报销 + 票据规则（2:50 - 4:20）

**操作**：
1. `sunqi` 发起差旅：开始/结束时间、预算；先演示结束早于开始 → 校验报错；改正后提交；
2. 详情页展示**系统计算出差天数**与口径说明（不足 24h 按 1 天）；`zhangsan` 批准；
3. `sunqi` 发起报销：关联已批准的差旅单；3 条明细，其中一条**无票**（填写无票原因），
   另两条上传票据；提交前故意把同一张票据放两条明细 → 提交被拒（同单票据去重）；改正后提交；
4. `zhangsan` 批准 → `wangwu` 财务审核：无票支出**红色高亮**、票据预览、合计金额（系统重算）→ 通过；
5. 再发起第二张报销复用同一张票据 → 提交成功但弹出**跨单重复票据预警**。

**口播**：
> 报销要求 ≥3 条明细、覆盖 5 类费用、每条须有票据或无票原因；合计金额由服务端重算，客户端不可信；
> 同单票据去重，跨单重复票据在财务审核界面预警高亮。

---

## 4. 驳回 / 撤回 / 复制 / 催办（4:20 - 5:00）

**操作**：
1. `zhouba / Zhouba@123` 提交一张采购单；`lisi / Lisi@123` 驳回——先演示**不填理由点驳回 → 报错**，再填理由驳回；
2. `zhouba` 在"我的申请"看到驳回原因，点**复制重提**生成新草稿，修改后重新提交；
3. 演示**催办**：`zhouba` 点催办 → 审批人收到通知；同节点再次催办 → 提示已催办过；
4. 演示**撤回**：`zhouba` 对另一张审批中的单撤回 → 状态 WITHDRAWN。

**口播**：
> 驳回必须填写理由；撤回与审批并发时由数据库行锁保证只有一方生效；重复点击提交不会产生两条流程。

---

## 5. 自定义流程模板（5:00 - 6:10）

**操作**：
1. 登录 `admin` → 流程模板 → 新建"用章申请"：
   - 表单字段：金额(number)、用章类型(radio)、合同编号(text，**显示条件**：类型=合同章时可见且必填)；
   - 审批节点：部门负责人审批 → 指定用户（管理员核签）；
2. 先做一次**发布失败演示**：删掉一个节点（剩 1 个）→ 点发布 → 展示校验错误清单；恢复 2 节点后发布成功（版本 v1）；
3. 编辑该模板改个字段 → 自动生成 **v2 草稿**，发布后 v2 生效、v1 自动停用（展示版本列表）；
4. 员工 `zhouba` 发起申请 → 可见该模板；类型选"公章"时合同编号隐藏（**条件显隐**），选"合同章"时必填；
5. 提交 → `lisi` 批准 → 流转到 `admin`（**指定用户节点**）：管理员待办中心出现任务，核签通过；
6. 关键演示：在流转到管理员之前，`admin` 直接访问该申请详情 → **403**（管理权限 ≠ 审批权限）。

**口播**：
> 模板支持 7 类字段、必填与显示条件、可排序的多节点审批链、至少两种审批人规则；
> 发布前服务端校验字段标识唯一、条件引用有效、节点完整；版本化发布，旧版本自动停用，已提交实例不受影响。

---

## 6. 统计与通知中心（6:10 - 6:50）

**操作**：
1. `sunqi` 工作台：个人统计卡片 + 近 6 个月提交趋势折线图（口径标注：按提交时间）；
2. `zhangsan` 工作台：部门统计（本部门各类型状态分布 + 已通过金额柱状图，草稿/驳回/撤回不计入）；
3. `admin` → 统计授权：给 `wangwu` 授予财务统计口径 → `wangwu` 可看报销+采购跨部门统计；
   撤销授权 → 立即 403（演示授权即时生效）；
4. 通知中心：未读角标、单条已读、全部已读、点击通知跳转到对应申请详情。

**口播**：
> 统计按提交时间口径，已通过金额不含草稿、驳回和撤回；部门统计按明确授权分级；
> 通知支持未读计数、去重与一键跳转。

---

## 7. 移动端响应式（6:50 - 7:20）

**操作**：浏览器开发者工具切到手机尺寸（375px）刷新页面，依次演示：
1. 抽屉式导航、发起申请（动态表单单列布局）、提交；
2. 待办中心审批操作；
3. 打开页面即自动加载最新数据（刷新/SSE）。

**口播**：
> 全部核心操作在移动端可用：发起、审批、查看进度与通知；页面打开自动拉取最新数据。

---

## 8. 收尾：从零复现 + 交付物（7:20 - 7:50）

**操作**：
1. 终端 `docker compose down -v`（删除数据卷）→ 再 `docker compose up -d` → 打开页面：全部演示数据恢复初始状态；
2. 快速展示仓库结构：`backend/sql/init/`（建表+种子脚本）、`docs/设计文档.md`、`docs/使用手册.md`、
   `docs/实验报告.md`、`docker-compose.yml`、git log（提交记录）。

**口播**：
> 一键重建环境即可完整复现演示；设计文档、使用手册、实验报告与代码同步交付。
